# ARCHITECTURE

## 목적

이 문서는 AI 산악사고 통합 대응 플랫폼의 전체 구성, 데이터 흐름, 권한 모델과 단계별 구현 범위를 설명합니다. 1차 구현은 경진대회 시연에서 안정적으로 동작하는 핵심 흐름을 우선합니다.

## 한 줄 요약

React + TypeScript + Vite 프론트엔드와 Python FastAPI 백엔드, PostgreSQL + PostGIS 데이터베이스를 Docker Compose로 구성하고 REST와 WebSocket으로 통신하는 웹 기반 산악사고 대응 플랫폼입니다.

## 구현 범위

`docs/PRODUCT.md`는 경진대회용 제품 전체 범위를 설명합니다. 개발은 다음 두 단계로 나눕니다.

### MVP 1차 구현

- 사고방 생성과 역할별 접속 링크
- 신고자 GPS 위치와 상태정보 입력
- 신고자·구조대 위치 지도 표시
- 기상·일출·일몰 정보
- 산 정보와 산악안전시설
- 규칙 기반 위험도 분석
- 구조장비 추천
- 실시간 문자 채팅
- 사고 종료와 기록 보존

### MVP 2차 구현

- 실제 등산로 기반 최적 구조 경로
- 신고자용 응급처치 챗봇
- 지휘관용 SOP 챗봇

STT, TTS, 영상통화와 고급 수색구역 분석은 MVP 이후 기능입니다.

## 주요 구성요소

### Frontend

- React + TypeScript + Vite
- Leaflet 지도
- 신고자 입력 화면
- 소방대원 관제 화면
- 지휘관 화면
- 실시간 채팅 UI
- REST API와 WebSocket 클라이언트

### Backend

- FastAPI REST API
- FastAPI WebSocket
- 사고·사용자 역할·토큰 검증
- 규칙 기반 위험도 계산
- 구조장비 추천
- 외부 공공데이터 연동과 캐시
- 사고기록 저장

### Database

- PostgreSQL + PostGIS
- 사고, 참여자, 위치 이력, 신고자 상태, 메시지 저장
- 위험도와 장비 추천 결과 저장
- 산·등산로·시설 지리정보 저장
- 기상정보 캐시

### External APIs

우선순위는 다음과 같습니다.

1. 소방안전 빅데이터 플랫폼
2. 기상청 단기예보·초단기실황·기상특보
3. 공공데이터 기반 일출·일몰 정보 또는 검증된 계산 방식
4. 산림청·공공데이터포털의 산·등산로 데이터
5. 국내 공공데이터가 부족할 때만 보조적인 외국 상용 API

실제 API를 연결하기 전에는 `DEMO_DATA_MODE=true`로 시연용 데이터를 사용합니다.

## 데이터 흐름 예시

신고자 위치 전송 흐름은 다음과 같습니다.

1. 사고 생성 시 신고자·소방대원·지휘관용 토큰을 각각 한 번만 노출합니다.
2. 신고자는 보안 링크로 접속하고 자신의 위치와 상태를 REST API로 전송합니다.
3. 백엔드는 토큰과 사고 상태를 검증합니다.
4. 위치를 PostGIS에 저장하고 같은 사고방의 권한 있는 사용자에게 WebSocket으로 전달합니다.
5. 위험도와 장비 추천을 다시 계산하고 결과를 저장합니다.
6. 소방대원과 지휘관 화면이 새 정보를 지도와 요약 카드에 반영합니다.
7. 사고 종료 후에는 새 위치·상태·채팅 입력을 차단하고 기존 기록은 보존합니다.

## 권한 모델

### 신고자 (reporter)

- 자신의 위치와 상태를 입력·갱신할 수 있습니다.
- 구조대와 문자 채팅을 할 수 있습니다.
- 다른 참여자의 개인정보와 위치정보는 볼 수 없습니다.
- 사고 종료, 권한 변경, 기록 삭제는 할 수 없습니다.

### 소방대원 (responder)

- 사고 참여자의 위치와 신고자 상태를 볼 수 있습니다.
- 관제 화면과 채팅을 사용할 수 있습니다.
- 사고를 종료하거나 권한을 변경할 수 없습니다.

### 지휘관 (commander)

- 소방대원 권한을 포함합니다.
- 사고 종료와 종료된 사고기록 조회 권한을 가집니다.
- 최종 구조 판단은 지휘관이 수행합니다.

### 관리자 (admin)

- 별도 관리자 인증을 사용합니다.
- 시스템 설정, 시연 데이터, 사용자와 감사기록을 관리합니다.
- 민감정보 조회는 업무상 필요한 최소 범위로 제한합니다.

## 토큰 체계

- 사고 생성 시 `reporter_token`, `responder_token`, `commander_token`을 각각 발급합니다.
- 토큰 원문은 발급 응답에서 한 번만 표시하고 데이터베이스에는 해시만 저장합니다.
- REST 요청은 `Authorization: Bearer <token>`을 사용합니다.
- 브라우저 WebSocket은 장기 토큰을 URL에 넣지 않습니다.
- REST에서 짧은 유효기간의 WebSocket 전용 토큰을 발급받고 `Sec-WebSocket-Protocol`로 전달합니다.

## 운영 고려사항

- 외부 API 키는 서버 환경변수로만 관리합니다.
- 지도 좌표는 WGS84, SRID 4326을 사용합니다.
- PostGIS 지리 컬럼에 GIST 인덱스를 사용합니다.
- WebSocket 재연결과 중복 메시지 처리를 고려합니다.
- 모든 시각은 저장 시 UTC를 사용하고 화면에서 한국 표준시로 변환합니다.
- AI와 규칙 기반 결과는 참고자료이며 현장 판단을 대신하지 않습니다.
