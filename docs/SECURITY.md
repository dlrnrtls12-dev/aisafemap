# SECURITY

## 목적

이 문서는 신고자의 위치·건강정보와 외부 API 비밀정보를 안전하게 처리하기 위한 최소 보안 기준을 정의합니다.

## 기본 원칙

1. 필요한 정보만 수집합니다.
2. 사용자는 역할에 필요한 최소 권한만 가집니다.
3. 비밀정보와 개인정보를 코드와 로그에서 분리합니다.
4. 민감정보 접근과 중요 동작을 감사기록으로 남깁니다.
5. AI 결과는 참고자료이며 사람의 최종 판단을 대신하지 않습니다.

## 민감정보 분류

### 고위험 정보

- 신고자 실시간 위치와 위치 이동 이력
- 이름과 연락처
- 건강·부상·복용약·알레르기 정보
- 사진·음성 등 개인을 식별할 수 있는 첨부정보
- 사고방 접속 토큰
- 간이구조구급함 비밀번호 등 제한정보

### 일반 또는 공개 가능 정보

- 공개된 산·등산로·시설 정보
- 공개 기상정보
- 개인정보가 제거된 통계

공개 데이터라도 출처, 이용조건과 갱신 시각을 기록합니다.

## 인증과 권한

### 역할별 권한

- 신고자: 자신의 위치·상태 입력과 채팅, 공개 가능한 구조 진행상황 조회
- 소방대원: 해당 사고의 신고자 상태·참여자 위치 조회와 채팅
- 지휘관: 소방대원 권한, 사고 종료와 기록 조회
- 관리자: 별도 관리자 인증, 시스템·시연 데이터·감사기록 관리

신고자는 다른 참여자의 위치나 개인정보를 볼 수 없습니다. 소방대원과 지휘관도 참여하지 않은 사고의 민감정보를 볼 수 없습니다.

### 접속 토큰

- 사고마다 `reporter_token`, `responder_token`, `commander_token`을 구분해 발급합니다.
- 토큰 원문은 발급 시 한 번만 표시합니다.
- 데이터베이스에는 원문 대신 HMAC-SHA-256 결과를 저장합니다.
- 역할 토큰은 REST의 Bearer 헤더로만 전달합니다.
- 사고 종료 시 새 입력 권한을 즉시 중지하고 토큰 만료 정책에 따라 조회 권한을 제한합니다.
- 구체적인 최대 유효기간과 갱신 정책은 기관 운영방침 확정 후 설정값으로 관리합니다.

### WebSocket 인증

- 장기 역할 토큰을 URL 쿼리 문자열에 넣지 않습니다.
- REST 인증 후 짧은 유효기간의 일회용 WebSocket 토큰을 발급합니다.
- 브라우저에서는 `Sec-WebSocket-Protocol`로 단기 토큰을 전달합니다.
- 토큰은 한 번 사용하거나 만료되면 재사용할 수 없습니다.

## 암호화 기준

### 전송구간

- 배포 환경은 HTTPS와 WSS를 필수로 사용합니다.
- 백엔드와 외부 API 사이도 TLS를 사용합니다.
- 로컬 개발에서만 localhost HTTP와 WS를 허용합니다.

### 저장구간

- 데이터베이스 비밀번호, API 키, HMAC 키와 암호화 키는 환경변수 또는 배포 환경의 Secret Manager로 관리합니다.
- GitHub에는 실제 비밀값을 커밋하지 않습니다.
- 건강정보, 정밀 위치정보와 제한정보는 애플리케이션 수준에서 인증된 암호화 방식으로 암호화합니다.
- 구현 시 AES-256-GCM과 같은 인증된 암호화를 사용하고, 암호화 키는 데이터베이스와 분리합니다.
- 백업도 암호화하고 접근권한을 제한합니다.

## 로그와 감사

일반 애플리케이션 로그에 다음 원문을 남기지 않습니다.

- 이름
- 전화번호
- 건강정보
- 전체 GPS 좌표
- API 키
- 접속 토큰
- 구급함 비밀번호

필요한 경우 좌표는 낮은 정밀도로 줄이고 식별자는 내부 UUID로 대체합니다.

감사로그에는 다음을 기록합니다.

- 누가 또는 어떤 역할이
- 언제
- 어떤 사고에서
- 어떤 종류의 민감정보를 조회·수정했는지
- 요청 식별자와 결과

감사로그 자체에는 민감정보 원문을 기록하지 않습니다.

## 외부 API 보안

- 소방안전 빅데이터와 기상청 등 외부 API 키는 백엔드에서만 사용합니다.
- 프론트엔드 번들에 비밀키를 넣지 않습니다.
- 외부 API 요청·응답 전체를 무분별하게 로그에 저장하지 않습니다.
- 호출 제한, 장애, 잘못된 응답에 대비한 검증과 캐시를 사용합니다.
- 시연 데이터와 실제 API 데이터를 화면에서 구분합니다.

## 사고 종료와 기록 보존

- 사고 종료 후 실시간 위치 수집, 상태 갱신과 채팅 송신을 중지합니다.
- 사고기록은 종료 후에도 보존합니다.
- 실제 보존기간은 관련 법령과 소방기관 기록관리 방침에 따라 확정합니다.
- 위치 이동 이력과 건강정보는 장기 보존 필요성을 별도로 검토합니다.
- 경진대회 시연에는 실제 개인정보를 사용하지 않습니다.
- AI 학습에는 익명화 또는 가명처리된 정보만 사용합니다.

## AI 안전 원칙

- 위험도와 장비 추천에 근거와 데이터 기준 시각을 표시합니다.
- UI와 API에 참고자료라는 안내를 포함합니다.
- AI가 출동 명령, 구조 중단, 환자 확정 진단, 의료행위 또는 헬기 출동을 결정하지 않습니다.

## 보안 점검 항목

- 비밀정보가 Git 기록에 포함되지 않았는지 확인
- 역할별 접근제어 테스트
- 종료된 사고의 쓰기 차단 테스트
- 좌표·건강정보 로그 마스킹 확인
- 토큰 재사용과 만료 테스트
- CORS 허용 출처 최소화
- 입력값 검증과 요청 크기 제한
- 의존성 보안 점검과 정기 업데이트
- 백업 복원 절차와 권한 확인
